# Changelog

## 0.3.0 — research correction round

* **Real device support:** added `--device auto|cpu|mps|cuda` and `resolve_device()` with explicit `RuntimeError` on unavailable `cuda`/`mps` (no silent fallback). Torch runs move the model and every split to the selected device and convert back with `.detach().cpu().numpy()`; the resolved device, requested device, torch/python/numpy versions, dtype, seed, epochs, optimizer (AdamW), learning rate, weight decay and `determinism_notes` are recorded per run and per payload.
* **Honest report generator:** removed every hardcoded claim (unconditional "PyTorch is not installed", "4,656 parameters" as a total, hardcoded "yield flat", hardcoded chance-level held-out wording). `write_report` now derives every sentence from the payload and always states backend scope, real setup, and the operational (non-statistical) nature of the ±0.05 rule.
* **Parameter accounting fixed:** NumPy now reports total 4,681 = frozen 4,656 + trainable 25; `architecture_parameters()` is documented as the frozen backbone subtotal only. Torch counts come from `model.parameters()`/`requires_grad`. Tests assert `total == trainable + frozen` for both backends and that counts are constant across loop counts.
* **`estimated_block_calls` clarified:** it is a structural counter of sequential shared-block applications, not FLOPs and not latency; measured `seconds` is reported separately, and it is documented that equal epochs are not equal compute budgets.
* **Experiment design:** baseline and looped configurations are asserted (and tested) to share identical initialization per seed; per-seed paired deltas vs baseline (and their mean/std/stderr) are stored and reported; **H2 is now computed and reported** (`drop(baseline) - drop(looped)` with `drop = in_distribution - heldout`), and H1/H2/H0 each carry an explicit `evaluated` status.
* **Split integrity:** train/dev are drawn as one joint pool of unique examples and randomly partitioned; held-out excludes train/dev examples. Exact `(length, tokens)` overlap is measured per seed, recorded, and asserted to be zero (it was 42–55 examples for train/dev under the previous independent-PRNG scheme). `make_splits` fails loudly when the example space is too small.
* **Torch artifacts:** `--artifacts-dir` writes `run.json`, `run.md`, `checkpoint_manifest.json` (per-file SHA-256/size, source commit + dirty state, data manifest/fingerprints, exact rerun command, per-seed raw results, paired summary) and a reload-and-re-evaluate check over every saved checkpoint. Checkpoints are gitignored (`results/*/checkpoints/`); only the manifest is tracked.
* **Optimization diagnostic:** a separate small overfit diagnostic (32 examples, lengths 4–8, distinct seed, never the held-out split) records a train loss/accuracy trajectory.
* **Docs:** DESIGN.md and README.md rewritten to match the code — "specified hypotheses and a fixed decision rule" instead of "preregistered" (with the commit-history caveat), corrected parameter tables, scoped literature statements and the corrected DSPy citation. The superseded NumPy smoke output was moved verbatim to `results/archive-v1/` (with a note recording the 42/55/50 train/dev example overlap it contained) and `results/smoke.json`/`results/smoke.md` were regenerated by the fixed writer from example-disjoint splits.
* Docs: removed the stale "PyTorch is not installed / Python 3.14" claims; the local environment is python 3.12.13 with torch 2.14.0 and MPS.
* **Honest negative stability finding:** the real MPS run trains end-to-end and is reported in `results/torch-mps-2026-09-15/`. Re-running the identical command was **not** bit-reproducible for looped-4 (paired held-out delta +0.0417 `flat` on the first run, +0.0573 `improvement` on the repeat), so the ±0.05 label is unstable near the threshold. This is recorded in README.md and DESIGN.md rather than hidden. H1 was not supported in the final run; H2 was supported for looped-2; H0 was not rejected.

## 0.2.0

* Added `pythonpath = ["."]` under `[tool.pytest.ini_options]` in `pyproject.toml` for seamless `pytest -q` execution.
* Added multi-seed execution support (`--seeds` flag, defaulting to seeds 7, 42, 123) with mean ± std aggregation across accuracy, cross-entropy loss, accuracy-by-length, and runtime.
* Added loop scaling ablation evaluating `baseline (loops=1)`, `looped (loops=1)`, `looped (loops=2)`, and `looped (loops=4)`.
* Verified architectural parameter invariance (transformer subtotal 4,656 across all NumPy models) while tracking linear compute scaling via `estimated_block_calls` (1, 1, 2, 4). *(Superseded in 0.3.0: 4,656 is the frozen backbone subtotal, not the total.)*
* Implemented specified hypothesis decision rules (`baseline (reference)`, `improvement`, `flat`, `regression`) based on held-out length performance. *(Corrected terminology in 0.3.0: these rules were not preregistered; DESIGN.md and the first results share commit 161752a.)*
* Strengthened test suite (`tests/test_data.py`, `tests/test_models.py`) with checks for length disjointness, absence of data leakage, bitwise determinism, parameter invariance, and PyTorch environment blocker errors.
* Updated `results/smoke.json` and `results/smoke.md` with multi-seed benchmark tables, length-wise metrics, and transparency notices.
* Updated CI workflow (`.github/workflows/ci.yml`) to execute `pytest -q` and the multi-seed smoke experiment.
* Documented Colab Pro / NVIDIA L4 execution instructions and documented the Python 3.14 PyTorch blocker. *(Stale as of 0.3.0: torch is installed locally; the Colab/NVIDIA instructions are removed.)*
